# 模型表情标准

本文定义 `model` 组件的表情字段、Morph 配方、分组、预设与宿主控制接口。组件根字段和头身组合见[模型资源格式标准](model_package_spec.md)；GLB 的 Morph Target 结构要求见[Humanoid 模型归一化标准](standardized_model_spec.md)。

## 1. 表情配方、分组与整体预设

表情由命名 Morph 配方、独立分组状态和整体组合预设组成。组状态提供可选的通用眨眼、默认说话与口型映射；渲染器不根据游戏、角色、表情或 Morph 名选择实现。

本节定义静态 Morph 配方和线性适配，不定义来源游戏的 Animator、Timeline、非线性面部调度或自动眨眼策略。

### 1.1 模型组件字段

以下字段属于 `head` 或 `integrated`，不由 `body` 提供。

| 字段 | 类型 | 含义 |
|---|---|---|
| `morphPoses` | `MorphPose[]` | 必需；可为空。可寻址的静态 Morph 配方 |
| `expressionGroups` | `ExpressionGroup[]` | 必需；可为空。可以独立选择状态的分组 |
| `expressions` | `ExpressionPreset[]` | 必需；可为空。供简单调用使用的整体组合预设 |
| `defaultExpression` | string | 可选；引用一个整体预设作为初始选择 |

没有整体预设时也可以使用分组。未指定 `defaultExpression` 时，各组初始选择自身 `states` 的第一项；不根据名称猜测 Neutral、normal 或 Open。

### 1.2 MorphPose

- `name`：组件内唯一、非空的配方名，是引用键，不要求与原游戏或 Morph 同名。
- `targets`：节点名 → Morph 名 → 数值。只列出该配方的贡献，省略项为零。
- 数值为有限实数；`1` 表示来源常用的 100% 权重，不进行隐式钳制。允许负数或大于 1，不代表任意外推都视觉合理。
- 配方不是另一张网格，也不是相对于当前脸部状态的增量；它是一组相对于 Morph 零权重状态的系数。

示例：

```json
{
  "name": "mouth.sad",
  "targets": {
    "Face": { "mouthSad": 1 }
  }
}
```

设配方 p 对实际 Morph m 的数值为 T[p,m]，调用者给出的独立配方权重为 q[p]，底层运算固定为：

```text
W[m] = Σ q[p] × T[p,m]
```

不对配方总权重归一化，不在最终输出处偷偷限制到 `[0,1]`，也不按声明顺序互相覆盖。所有输入和结果必须有限；非法数值报错。原游戏若有特定限幅、互斥或优先级，不因使用这个通用加权和就自动得到还原。

### 1.3 ExpressionGroup

| 字段 | 含义 |
|---|---|
| `name` | 组件内唯一的分组名；由数据定义，不限制为 face/eyes/mouth |
| `states` | 非空数组；一个分组同时选中一个状态 |
| `states[].name` | 分组内唯一的状态名 |
| `states[].poses` | 基础配方权重表：配方名 → 有限实数；省略配方的系数为零 |
| `states[].controls` | 可选；此状态提供的通用控制映射 |

示例：

```json
{
  "name": "mouth",
  "states": [
    {
      "name": "Sad",
      "poses": { "mouth.sad": 1 },
      "controls": {
        "speech": { "mouth.a": 1 },
        "visemes": {
          "a": { "mouth.a": 1 },
          "i": { "mouth.i": 1 }
        }
      }
    }
  ]
}
```

分组依据真实可组合能力建立，不根据 Morph 名称强行拆分解剖部位。一个无法拆开的整体形变可以只有一个分组；不要求所有来源都拆成眼、眉、嘴三个组。

没有控制映射的状态仍然有效。固定闭眼或 Wink 不必为了接口齐全而生成无意义控制。

### 1.4 状态的 controls

| 字段 | 类型 | 通用语义 |
|---|---|---|
| `blink` | PoseWeights | 施加最大眨眼控制后的配方系数端点 |
| `speech` | PoseWeights | 默认说话嘴态的配方系数端点 |
| `visemes` | 名称 → PoseWeights | 可选发音目标；`a/i/u/e/o` 使用这些共同标识 |

`PoseWeights` 直接是配方名 → 系数，不套只有一个值的内层对象。三个字段都可省略。

通用输入的含义：

- `blink ∈ [0,1]`：0 保持当前基础眼态，1 施加此状态支持的最大眨眼控制。不是强制睁开/闭合一切眼态。
- `speech ∈ [0,1]`：0 保持配置的基础嘴态，1 到达默认说话目标。不是物理开口距离，也不保证 0 必然闭嘴。
- `visemes` 输入：口型名 → `[0,1]` 系数，系数和不大于 1；剩余份额保留基础嘴态。这是高层口型过渡规则，不是来源原始口型的任意独立强度接口。

`speech` 与 `visemes` 是同一嘴部输入的两个替代用法，不叠加执行。普通说话输入使用 speech；具备口型识别的调用方才提供 visemes。visemes 允许多个目标同时非零，不再只有离散的“选一个最大口型”。

#### 端点补全和计算

令当前组的基础系数为 b[p]。对控制端点 E：

```text
e[p] = E[p]，若端点显式给出 p
e[p] = b[p]，若端点省略 p
```

所以省略不是清零。需要撤掉一个基础配方，必须写显式的 `0`。

```text
眨眼贡献：       blink × (eBlink[p] - b[p])
默认说话贡献：   speech × (eSpeech[p] - b[p])
口型混合贡献：   Σ viseme[k] × (eViseme[k,p] - b[p])
当前组系数：     b[p] + 眨眼贡献 + 所选嘴部输入的贡献
```

每个口型端点先分别相对同一个 b 补全，再一次求和，不依次覆盖。未声明的控制对此组贡献为零。

同一状态的 blink 与嘴部控制不能改变同一实际 Morph：校验应展开配方后的差值检测，不仅比较配方名字。确有眼嘴耦合的来源行为不能假装是两个独立控制，需留待有证据的专项表达方案。

不同组的系数最终汇总后按 §1.2 求值。若两个组有重叠 Morph，贡献相加，不由组顺序决定；资源制作者须确保这种重叠符合预期。标准不承诺任意选项组合都天然美观。

#### 保留与替换基础配方

基础为 `{ "mouth.sad": 1 }` 时：

```json
{ "speech": { "mouth.a": 1 } }
```

表示 Sad 保持 1，A 从 0 增至 1。

```json
{ "speech": { "mouth.sad": 0, "mouth.a": 1 } }
```

表示 Sad 从 1 降至 0，A 从 0 增至 1。两种都可表达，由模型映射决定；播放器不需要 Sad 特判。

### 1.5 整体预设 ExpressionPreset

- `name` 在组件内唯一。
- `selections` 为分组名 → 状态名，必须完整选择本组件的所有分组，避免同一预设依赖之前选过什么。
- 不再直接携带 Morph 目标或开合端点；控制由被选中的组状态提供。
- 预设是便捷入口，不限制调用方随后独立更换某一组。
- 不要求导出所有组合的笛卡尔积。只保留来源有意义的整体预设和明确选定的适配预设。
- 预设名是不透明标识，播放器不解析其中的前缀或后缀；调用方可根据分组列表自行组合。

示例：

```json
{
  "name": "Sad",
  "selections": { "face": "Sad", "mouth": "Sad" }
}
```

### 1.6 完整字段示例

以下为模型组件内片段，省略 type/name/model 等既有字段；节点和形态名仅为示例。

```json
{
  "morphPoses": [
    { "name": "face.sad", "targets": { "Face": { "eyeSad": 1, "browSad": 1 } } },
    { "name": "eyes.close", "targets": { "Face": { "eyeClose": 1 } } },
    { "name": "mouth.sad", "targets": { "Face": { "mouthSad": 1 } } },
    { "name": "mouth.a", "targets": { "Face": { "mouthA": 1 } } },
    { "name": "mouth.i", "targets": { "Face": { "mouthI": 1 } } }
  ],
  "expressionGroups": [
    {
      "name": "face",
      "states": [
        {
          "name": "Sad",
          "poses": { "face.sad": 1 },
          "controls": { "blink": { "eyes.close": 1 } }
        }
      ]
    },
    {
      "name": "mouth",
      "states": [
        {
          "name": "Sad",
          "poses": { "mouth.sad": 1 },
          "controls": {
            "speech": { "mouth.a": 1 },
            "visemes": {
              "a": { "mouth.a": 1 },
              "i": { "mouth.i": 1 }
            }
          }
        },
        {
          "name": "Neutral",
          "poses": {},
          "controls": {
            "speech": { "mouth.a": 1 },
            "visemes": {
              "a": { "mouth.a": 1 },
              "i": { "mouth.i": 1 }
            }
          }
        }
      ]
    }
  ],
  "expressions": [
    { "name": "Sad", "selections": { "face": "Sad", "mouth": "Sad" } }
  ],
  "defaultExpression": "Sad"
}
```

### 1.7 控制语义与接口示例

自动眨眼时序与音频分析由应用负责；整体表情与单组状态切换的平滑由表情控制器负责。

#### 简单语义控制

```js
face.setExpression("Sad");
face.setBlink(1 - eyeOpen);
face.setSpeech(mouthAmount);
```

它只枚举整体预设，继续自行生成眨眼和说话输入；不读取节点、Morph、游戏名或配方。开眼值转眨眼值只是消费适配中的一次方向变换，不在模型里增加转换标记。

下游不能把 mouthAmount 当作跨模型可测量的口腔开口百分比；它是所选映射的进度。若应用要求静音时一定闭嘴，转换器必须提供经确认的闭嘴基础姿势及相应状态/预设；通用播放器不选择或推断模型的闭嘴配方。

#### 独立分组选择

```js
face.setGroup("mouth", "Neutral");
// 保留当前 face 组，只更换 mouth 组。
face.setSpeech(0.6);
```

例子中的组名是模型数据，不表示所有模型都有 mouth 组。只需说话控制的调用方
直接使用 `speech` 语义，无须定位特定分组。

需要一个完整表情名的下游，可以把 selections 保存为自己的预设；不能仅靠拆解带连字符的名字恢复选择关系。

切换整体预设或单组状态时可提供以秒计的非负有限过渡时长；`0` 表示立即切换。过渡在配方系数层对切换前已求值的结果与新状态求值结果线性混合；中途再次切换从当前结果开始。blink、speech 和 visemes 保持原输入，目标状态按当前输入求值。Morph 和 Behavior 读取同一份过渡后的配方系数。模型首次加载、重置和低层配方写入不自动发起过渡。

#### 口型混合输入

```js
face.setVisemes({ a: 0.4, i: 0.2 });
// 0.4 A 目标姿态 + 0.2 I 目标姿态 + 0.4 基础嘴态；不再额外应用 speech。
face.setSpeech(0.7); // 明确切回默认说话输入。
```

系数之和大于 1，或存在负数、非有限值时，高层口型输入无效，不能静默归一化。
空对象表示只使用基础嘴态；退出口型输入后恢复此前的 speech 值。示例 API 分别用
`setVisemes({})` 和 `setVisemes(null)` 表达这两种状态。

有效口型名集合是本组件所有分组、所有状态的 visemes 键的并集；主动提交不在这个集合中的名字应报错。当前可用集合只取已选状态的并集。输入在模型中有效、但当前状态没有映射时，对该组贡献为零、不重新分配给其他口型；切换状态也遵循这一规则。剩余贡献自然回到新基础嘴态。宿主如提供能力查询，可分别返回全部有效名称与当前可用名称。

#### 低层配方混合

```js
face.setMorphPoseWeights({ "mouth.sad": 1, "mouth.a": 1 });
```

这条低层接口独立混合配方，不要求系数和为 1，不应用组状态或通用控制映射。它不是跨所有模型共享的语义接口，也不意味着原游戏会自动生成这个组合。

低层输入与分组输入互为运行时写入来源，不能同时写同一张脸。切换到低层输入时
停止分组求值；再次选择整体预设或分组状态时恢复分组求值。blink/speech/visemes
在低层控制时可以保存输入，但不叠加到低层结果。以上为运行时状态，不在资源中
增加模式标记字段。

### 1.8 状态、能力与写入规则

1. 每次求值从当前输入重建结果。受管 Morph 为所有 morphPoses 引用目标的并集；未贡献的受管目标回到零，不残留上一帧或上一状态的值。完全不在该集合的 Morph 不由本系统接管。
2. 切换整体预设或单组状态保留 blink、speech 以及当前口型输入；新状态按新映射求值，旧状态的配方结果仅在有限时长的过渡内参与混合，过渡结束不残留。这样换表情不必先打断正在进行的眨眼或说话。
3. 重置时返回默认选择，清零 blink/speech，退出口型及低层输入。资源卸载释放控制权。
4. 是否有 blink、speech 和 visemes 映射由所选组状态决定；没有映射不等于加载失败。
5. 非法引用、重复标识、非有限数值、控制输入越界必须明确报错。校验依据是本文声明的数据形状、数值范围和引用关系。
6. Morph 目标按 GLB JSON 中原始、大小写敏感的 `node.name` 和 `mesh.extras.targetNames` 寻址。引用的节点名在组件内必须恰好命中一个节点，Morph 名在其 mesh 内非空且唯一；零命中或多命中必须报错。该节点的所有 primitive 及其运行时绘制实例须呈现相同的目标权重。
7. 启用表情控制时，其结果覆盖受管 Morph 上的动作写入；停用后撤去表情结果，由动作或其他合法写入者接管。宿主不得把上一帧的表情结果当作动作基础姿态，也不得在停用后冻结旧表情权重。TRS 和显隐不因此被接管。
8. Behavior 如果也要拥有这些 Morph，宿主必须明确交接控制权，不能依赖任意的写入先后碰撞。Behavior 的输入与生命周期仍由 Behavior 规范定义。

表情定义及已完成求值的运行状态可通过 Behavior 的只读查询取得，具体返回字段、
配方系数与停用语义见 [model_behavior_spec.md](model_behavior_spec.md) §6.1、§6.3。
该查询不扩展表情资源的写入目标；TRS 和显隐仍不属于 Morph 配方。
