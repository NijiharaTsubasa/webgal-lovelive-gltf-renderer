# 参数驱动动作与表情规范（可选扩展）

本文面向 BanG Dream 剧情二创社区使用的特定 Live2D 参数体系。

本扩展使标准化三维角色能够直接使用该体系的 `.mtn` 动作与 `.exp.json` 表情。
来源参数描述的运动由共享规则映射为 Humanoid 骨骼运动；面部参数由与目标模型
`motionGroup` 匹配的 JavaScript 适配器解释。用户可以分别选择动作和表情，
也可以将它们与标准三维动作、模型自带表情交叉使用。

这些参数来自同一系列模型，但相同数值在不同来源角色上的幅度和图案可能不同。
本文规定参数含义、播放组合与适配接口；三维表达以正面及小角度观察时形似、神似
为目标，不把二维形变解释成唯一、精确的三维姿态。

## 1. 资源格式与适配器声明

来源动作以 `.mtn` 文件交付，来源表情以 `.exp.json` 文件交付。应用通过资源路径
定位文件，并分别选择动作和表情；同名文件不隐含配对关系。
动作采用 `500` 毫秒的淡入、淡出时间，表情的淡入淡出读取 `.exp.json`，见 §3.1。

目标面部适配器使用[统一资源包清单](resource_package_spec.md)的 `components`，
类型为 `garupa-expression-adapter`；`garupa` 标识本文限定的来源参数体系。

### 1.1 适配器字段

| 字段 | 含义 |
|---|---|
| `type` | `garupa-expression-adapter` |
| `name` | 非空适配器资源名 |
| `description` | 人类可读说明，可省略或为空字符串 |
| `motionGroup` | 此适配器处理的目标模型兼容域，非空字符串 |
| `script` | 包内 JavaScript 模块路径，接口见 §5 |

除 `description` 外，以上字段均为必需。适配器以 `motionGroup` 作为匹配键，
同一有效资源集合中一个域只能有一个适配器，不能按扫描顺序选择或覆盖。

同一份来源动作或表情可以用于不同三维模型。

### 1.2 示例

```json
{
  "components": [
    {
      "type": "garupa-expression-adapter",
      "name": "face-adapter",
      "description": "参数表情适配器",
      "motionGroup": "example-face",
      "script": "face.js"
    }
  ]
}
```

适配器文件可以平铺，也可以放在子目录，并可以随模型的 Shader、Behavior 一起交付。

## 2. 来源参数

参数 ID 区分大小写。以下表格中的 `L/R` 表示角色自身的左／右；正视图中角色
右侧位于屏幕左侧。表内省略共同前缀 `PARAM_`，实际文件和接口必须使用完整 ID。

表中的“常用区间”用于解释测量结果，不是文件合法性的上下限。实际资源中存在
超出这些区间的值，不能因此拒绝整个动作或表情，也不能把所有参数统一钳制到
`[0,1]`。尚无共享解释的参数保留原 ID 和数值，不通过相似名字推断其用途。

### 2.1 初始值

无角色绑定的播放实例以一份共享参数基线开始：左右 `EYE_*_OPEN` 为 `1`，
左右 `HAND_*_01_001` 为 `1`，本节其余参数为 `0`。输入中的其他参数在首次赋值
前按 `0` 处理。动作或表情未写入某个参数，不等于每帧把它重置为初始值；
后续值由 §3 的参数基线与覆盖规则决定。

这里的初始值是本扩展的共享播放约定。它不等于每个来源角色看起来完全相同的
中性姿态，也不要求动作携带某个来源角色的 MOC。

### 2.2 身体、头部与手臂

| 参数 | 常用区间 | 来源含义及三维表达要点 |
|---|---|---|
| `POSITION_X/Y` | `[-1,1]` | 整体平移，正值向屏幕右／上；使用整体位移，不由肩或颈补偿 |
| `ROTATION_Z` | `[-1,1]` | 整体画面内转动，含旋转支点引起的位移；来源先施加 POSITION 再旋转 |
| `BODY_ANGLE_X` | `[-10,10]` | 躯干左右转向的二维形变，不是画面内侧倾 |
| `BODY_ANGLE_Y` | `[-10,10]` | 躯干共同起伏并伴随局部压缩，不能只解释成头部点头或独立耸肩 |
| `BODY_ANGLE_Z` | `[-10,10]` | 躯干侧倾及支点位移，肩部随躯干共同运动 |
| `UPPER_BODY` | `[-1,1]` | 上半身探身／收身形变，正负两段不互为反向线性位移 |
| `BREATH` | `[0,1]` | 胸部呼吸起伏；曲线没有写入时，不自行生成周期运动 |
| `ANGLE_X/Y` | `[-30,30]` | 左右转头／抬低头的二维形变；参数值不直接等于三维角度 |
| `ANGLE_Z` | `[-30,30]` | 头部画面内转动，不带动整个人旋转 |
| `ARM_{L,R}_01_001` | `[-30,30]` | 上臂绕肩侧支点转动，带动前臂和手 |
| `ARM_{L,R}_01_002` | `[-10,60]` | 前臂相对上臂转动，同时改变二维投影长度 |
| `ARM_{L,R}_01_003` | `[-10,10]` | 手相对前臂的画面内转角，不是单纯绕前臂轴扭转 |
| `ARM_{L,R}_CHANGE` | `[0,1]` | 手臂相对身体及另一侧手臂的遮挡顺序，0 在身体前、1 在身体后；不提供真实深度，也不决定掌心朝向 |

默认参数动作渲染按来源排序分开绘制左右前臂与手，各侧保留原材质的全部 Pass
及自身深度检测。同一前后层内，手片排序值较小的一侧先绘制，排序值相同时
右侧先绘制、左侧后绘制。身体与上臂维持身体层的绘制方式。

手臂参数是层级相对控制，不能把来源各级累计方向分别当成局部关节旋转。
前臂二维转角可能超过人体肘屈曲范围，需要在三维肩、肘、腕之间合理分配，
不能全部变成某一个关节的轴向扭转。

### 2.3 手型

`HAND_{L,R}_XX_001` 是手图权重，通常为 `[0,1]`，不是手指关节角。
多个权重可以同时非零，用于手图之间的过渡。三维侧使用共享的七组手型及其
朝向，并在手臂运动中保留相应的手掌关系。

| 手型 | 左手 `XX` | 右手 `XX` | 视觉含义，以自然下垂时为描述基准 |
|---|---|---|---|
| 1 | `01` | `01` | 自然弯曲，掌心朝内，拇指朝前 |
| 2 | `02` | `02` | 手指张开且有弯曲，中指与无名指靠拢；掌心朝外、小指侧朝前 |
| 3 | `03` | `03` | 与 2 相近的张手，手背侧朝前，拇指可见 |
| 4 | `04` | `04` | 手掌朝前的张手，用于招呼或挥别 |
| 5 | `05` | `05` | 握拳，掌心朝外、小指侧朝前，拇指收在内侧 |
| 6 | `06` | `06` | 张手的侧面视图，掌心朝外、小指侧朝前 |
| 7 | `07` | `09` | 与 5 朝向相近的半松拳，拇指仍被遮挡 |

原图的透视和轮廓不一定对应严格可实现的三维手。三维混合可以近似姿态变化，
但不能逐像素复制两张半透明手图同时出现的效果。

### 2.4 眼睛与眉毛

| 参数 | 常用区间 | 含义 |
|---|---|---|
| `EYE_{L,R}_OPEN` | `[0,1.5]` | 单眼开度，0 闭眼、1 通常睁眼，大于 1 为超开 |
| `EYE_{L,R}_SMILE` | `[0,1]` | 与开度共同决定闭眼／半闭眼的弧形，不代表整脸微笑 |
| `EYELID_{L,R}` | `[-1,1]` | 薄眼皮线的位置，正值上移；不是另一套眼睛开合 |
| `EYE_BALL_X/Y` | `[-1,1]` | 两眼虹膜共同向屏幕右／上移动 |
| `EYE_SCALE` | `[-1,1]` | 虹膜大小，正值变大；不放大眼白或眼皮 |
| `BROW_{L,R}_X` | `[-1,1]` | 单眉横向移动，正值远离鼻子，负值靠近鼻子 |
| `BROW_{L,R}_Y` | `[-1,1]` | 单眉上下移动，正值上移 |
| `BROW_{L,R}_ANGLE` | `[-1,1]` | 单眉倾角，正值使靠近鼻子的眉端抬高 |
| `BROW_{L,R}_FORM` | 常见 `[-1,1]` | 单眉弯曲形状，通常负值下凹、正值上拱；与倾角不同 |

`SMILE` 与 `OPEN`、眉形与眉角等需要组合解释。分别把每项机械映射到一个
完整预设，再叠加这些预设，会丢失这种关系。

### 2.5 嘴部与装饰

| 参数 | 常用区间 | 含义 |
|---|---|---|
| `MOUTH_OPEN_Y` | `[0,1]` | 当前嘴型的开度，0 闭合、1 张开 |
| `MOUTH_FORM_01` | 常见 `[-1,1]` | 嘴型，正半区通常偏宽／笑，负半区通常偏窄／嘴角下垂；同时影响开口轮廓 |
| `MOUTH_FORM_Y` | `[-1,1]` | 整口上下位置，正值上移，不是开度或嘴角曲率 |
| `MOUTH_SCALE` | `[-1,1]` | 整口大小，正值变大 |
| `CHEEK`、`CHEEK2` | `[0,1]` | 两种不同脸红图案的强度 |
| `TEAR` | `[0,1]` | 眼泪图案的显现，伴随少量位移／形变 |
| `EYE_HIGHLIGHT` | `[0,1]` | 眼球高光图案的大小／位置变化，不是高光透明度开关 |
| `EYE_FORM` | `[-1,1]` | 附加眼型；来源角色间响应差异明显，尚无可靠的统一形状解释 |
| `EYE_BROWS` | `[0,1.5]` | 部分来源角色的额外眉部图案显隐，不是普通眉毛平移 |
| `MOUTH_SWITCH` | `[0,1]` | 部分来源角色的两套口部图案切换 |
| `MOUTH_OPEN_Y_MANUAL` | `[0,1]` | 与额外口部切换关联的开度控制，具体组合规律尚未完整恢复 |

最后三项并非每个来源模型都有。适配器仍能收到它们，不因当前目标缺少相应
素材或尚无可靠映射，就在通用播放层提前删除参数。

### 2.6 表达范围

身体输出遵循[标准动作规范](standardized_motion_spec.md)的核心骨旋转、Hips
位移及其坐标语义，共享同一套映射与标定，不为每个目标模型生成另一套动作。
源参数的二维局部缩放、头发飘动、服装切换及部件透明度不由这些骨骼通道承载。

面部适配器可以直接操作 Morph、辅助节点与材质，或创建实例私有的派生几何，
不局限于混合模型已有的命名表情。可见能力取决于目标模型；没有独立泪图案时，
“改成悲伤眼型”不等于实现了眼泪参数。

## 3. 动作、表情与自动控制的组合

### 3.1 MTN 与 EXP

`.mtn` 保存随时间变化的参数曲线。`.exp.json` 保存参数目标值和淡入淡出时间，
不是逐帧表情动画。看到换表情时脸在运动，可能同时来自 MTN 曲线和 EXP 的
进入／退出过渡，不能只从文件同名判断来源。

本扩展采用已核验的 WebGAL-MyGO 覆盖式表情行为：

| EXP 字段 | 含义 |
|---|---|
| `fade_in`、`fade_out` | 毫秒；正值生效，省略或非正值按 `500` |
| `params` | 有序参数条目数组，未列出的参数不由该表情修改 |
| `params[].id` | 来源参数 ID |
| `params[].val` | 来源目标值 |
| `params[].def` | 加载时用于归一化的参考值 |
| `params[].calc` | 加载时的归一化方式，省略按 `add` |

加载时得到目标值 `v`：`add` 使用 `val - def`（缺省 def 为 0），`mult` 使用
`val / def`（缺省或零 def 按 1），`set` 使用 `val`。之后每帧按该条目的表情
权重 `w` 顺序应用：

```text
当前值 = 当前值 × (1 − w) + v × w
```

这里的 `add`、`mult` 不代表每帧继续对底层参数相加或相乘。切换 EXP 时，退出
和进入表情可能同时参与；不能先各自映射成整张三维脸，再用一个整脸权重代替
来源的逐参数覆盖。EXP 没有列出的参数继续保留底层结果。

### 3.2 每帧顺序与参数基线

```text
保留的参数基线 → MTN 更新 → 保存本帧基线
    → EXP 队列 → 自动眨眼 → 说话开度覆盖
    → 完整最终参数 → 身体映射／目标面部适配器
```

EXP、眨眼和说话的临时结果不回写为下一帧 MTN 的基线，避免累加漂移。
MTN 停止或自然结束不自动重置全部参数；在未发生显式重置或后续写入时，
保留它形成的基线。EXP 选择保持有效，直到切换或撤销。

淡入淡出需要处理非端点和中途打断，不是对已经映射的三维骨骼／整脸结果简单
线性插值。身体与面部消费同一时刻的参数状态，不能分别推进两个来源时钟。

### 3.3 眨眼和说话

- 自动眨眼量 `b ∈ [0,1]`：在当帧没有 MTN 更新时，将左右眼开度分别乘以
  `1-b`。保留来源表情的半闭眼；有 MTN 更新时不再叠加这层自动眨眼。
- 说话开度 `s ∈ [0,1]`：启用时最后覆盖 `PARAM_MOUTH_OPEN_Y`，不覆盖嘴型、
  眉毛或其他参数。释放说话控制后，重新使用 MTN／EXP 的开度。
- `s=0` 是持续闭嘴控制，不等于释放控制。眨眼时序和音频到开度的生成由宿主提供。

传给适配器的参数已经包含这两层作用，适配器不再额外叠加一次模型原生的
`blink` 或 `speech`。选择模型原生表情时，则继续使用原生表情标准的控制映射。

## 4. 身体与表情独立选择

身体来源可以是标准三维动作或 `.mtn` 参数动作；面部可以使用模型原生表情，
也可以使用来源参数表情。换动作不清除所选表情，换表情不重启动作。

| 组合 | 身体 | 面部 |
|---|---|---|
| 参数动作＋参数表情 | 共享参数映射 | MTN 面部曲线、独立 EXP 与眼口控制的最终结果 |
| 标准三维动作＋参数表情 | 标准动作播放器 | EXP 与眼口控制；若没有另行播放的 MTN，则没有其面部曲线 |
| 参数动作＋模型原生表情 | 共享参数映射 | 原生表情及其眼口控制；不应用来源面部参数 |

没有选 EXP 也可以使用 MTN 自身的面部曲线。撤销 EXP 只撤销该队列的作用，
不等于退出整个参数面部模式；退出该模式时才恢复原生表情控制。

标准动作中匹配 `motionGroup` 的专属轨道可以先写入模型；参数表情随后覆盖
它所接管的面部属性，其他属性保持不变。退出参数表情后，动作和原生表情按
各自当前状态继续求值，不冻结在进入参数表情时的旧姿态。

## 5. 目标面部适配器

### 5.1 匹配与创建

宿主按完整角色的有效 `motionGroup` 查找 `garupa-expression-adapter`。
一体模型使用自身值；头身组合沿用[模型资源格式标准](model_package_spec.md)
的有效域规则，不能用模型 `group` 或来源动作目录名代替。

没有有效域或没有匹配适配器时，不应用来源面部参数，也不暂停原生表情；
参数身体动作仍可播放。一个域中有多种脸部结构时，适配器根据模型实际数据
判断能否处理；不支持的结构可以返回 `null`，效果同没有适配器。

脚本命名导出工厂，每个角色实例独立创建，不共享可变的脸部状态：

```js
export function createExpressionAdapter(context) {
  // 若本模型结构不能处理，返回 null。
  return {
    restore() {},
    apply(parameters, frame) {},
    dispose() {}
  };
}
```

### 5.2 `context`

| 字段／方法 | 含义 |
|---|---|
| `THREE` | 宿主使用的 Three.js 模块 |
| `root` | 组合完成的角色根节点 |
| `parts` | 已加载模型组件，条目含 `role`、`component`、`gltf`、`root`，含义沿用 Behavior 规范 |
| `resolveNode(role, name)` | 沿用 Behavior 规范的原始节点名解析接口 |
| `getShaderRuntimes(material)` | 取得该运行时材质的 Shader JS 实例数组；没有则为空数组 |

`component` 包含模型自己的表情、Behavior 参数等元数据。适配器可以据此绑定
实际 Morph 和辅助节点，不读取宿主私有的表情控制器或节点索引。

Shader 实例的专有能力由该 Shader JS 与适配器协作实现，例如更新脸红强度；
通用宿主不识别这类专有方法名。适配器代码与其资源使用包内引用，可复用同包
Behavior 的内部求值工具；模型自带表情仍使用原有 Behavior 语义。

### 5.3 输入与生命周期

`parameters` 是完整的、只读的 `参数 ID → 有限数值` 表，包含 §2 的初始项和
当前已读入的其他参数，值已经完成 §3 的组合。它不是仅含变化项的补丁，
也不是仅含此适配器支持项的过滤结果。适配器不重新解析 MTN／EXP，不根据
动作名或表情名猜测当前状态。

```js
adapter.apply(parameters, {
  time: 1.25,  // 当前来源播放时钟，秒；定位播放时可以回退
  delta: 1 / 60 // 本次更新经过的时间，秒；重新采样可以为 0
});
```

三个方法的职责如下：

| 方法 | 职责 |
|---|---|
| `restore()` | 撤销上一帧适配器的临时覆盖，露出底层状态；未应用过时不做修改 |
| `apply(parameters, frame)` | 在本帧底层动作、Behavior 与物理完成后应用面部结果，并保存恢复所需的底层值 |
| `dispose()` | 撤销残余覆盖，释放实例创建的几何、材质等资源；不销毁模型共享资源 |

创建成功并启用参数面部模式后，宿主暂停原生表情写入，但保留原生选择和控制值。
每帧先 `restore()`，再取得底层动作、Behavior 与物理的结果，最后 `apply()`，随后进入绘制。
停用或更换适配器时恢复底层状态，再恢复原生表情；模型卸载时销毁适配器。

适配器只能覆盖自己使用的属性，不能每帧清空整个角色的 Morph 或重置全部
辅助节点。TRS、显隐、材质输入和派生几何都遵循同样的撤销与实例隔离要求。
对于由模型自身 Behavior 管理的面部辅助属性，适配器需处理其外部控制状态，
不能只改 Morph 而让 Behavior 随后依据旧预设覆盖结果。

## 6. 来源播放与现有规范

标准动作与模型自带表情分别遵循其对应规范。模型的有效
`motionGroup` 用于适配器匹配；标准动作的 `motionGroup` 仍只决定其专属轨道匹配。

参数含义与共享三维映射依据见[身体参数测量](live2d-body-mapping-evidence.md)、
[手臂参数测量](live2d-arm-mapping-evidence.md)及
[面部组合与测量记录](live2d-webgal-face-policy.md)。具体目标模型的能力限制
由对应适配器说明，不固化为所有模型必须采用的限幅或变形算法。

MTN 的曲线采样及队列淡入淡出沿用 Cubism 2 格式的播放语义；EXP 的覆盖方式
使用 §3.1。可以调用来源运行库，不要求重新实现其曲线求值器。

不绑定来源角色的共享求值使用 §2.1 的初值。来源曲线求值需要参数范围时，
使用 §2 表格列出的区间（眉形和嘴型统一使用 `[-1,1]`）；其他参数提供
`[-1,1]` 的参考区间。该范围用于来源曲线求值，不对最终参数再做全局截断。
适配器始终收到有限的原始数值，目标表达能力的限幅由适配器自身处理。
